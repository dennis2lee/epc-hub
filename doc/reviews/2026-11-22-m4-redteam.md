# M4 레드팀 검토 (시범 준비: 배포·보안, 시범 운영)

- 날짜: 2026-11-22
- 검토자: Fable 레드팀 2개(배포·보안, 시범 운영·실사용자). 후속 결정은 Fable 정책 자문 1개
- 대상: `doc/deploy.md`, `doc/operations.md`, `doc/device-checklist.md`, 로그인·초대·관리자·Cron·알림 코드, 마이그레이션 전체
- 조치 마이그레이션: `src/supabase/migrations/20261122000100_m4_review_fixes.sql`
- 관련 결정: D27~D39 (`doc/decisions.md`)
- 한계: 클라우드 프로젝트가 아직 없어 Vercel·Supabase 클라우드에서는 아무것도 시험하지 못했다. "추정"은 코드와 공급자 문서를 읽고 판단한 것이다.

## 요약

배포·보안 팀은 14건을 냈다. 높음 2건은 다음과 같다.

- 로그인 후 이동 주소 검사를 점 경로(`/.//evil.com`)로 우회할 수 있었다. 재현했다.
- 배포 절차에 Supabase 인증 메일 설정(SMTP, OTP 10분·6자리)이 없어 첫 주일에 로그인 코드가 거의 오지 않았을 것이다.

시범 운영 팀은 15건을 냈다. 높음 5건은 모두 "현장에서 반드시 일어나는데 앱이나 절차서에 길이 없는" 문제였다.

- 다른 방법으로 로그인한 교인을 되돌릴 방법이 없다.
- 메일 없는 작성자는 보완 요청을 받지 못하고, 아무도 그 사실을 모른다.
- 첫 관리자 설정 절차와 시범 시작 점검표가 없다.
- 백업 절차서가 존재하지 않는 작업을 설명한다.
- 연초 직책 교체 순서가 틀렸다.

화면 이름·버튼 이름은 절차서와 앱이 일치했다. 실제와 맞는지 확인한 사항은 7일 초대 기한, 5회 잠금, 관리자 본인 대면 확인 금지, 무효·결제·정정 흐름, 월요일 "이상 없음" 메일이다.

## 보류한 것

- 인증 CAPTCHA, 또는 Supabase "가입 전" 훅으로 초대된 주소·카카오 계정만 가입 허용(D27의 남은 위험).
- 결재 대결(위임) 기능.
- 백업 자동화(암호화 덤프를 교회 소유 버킷으로).
- 제출 전에 중복 의심을 보여 주고 확인받는 단계.
- 청구서 전체 목록과 인쇄본 일괄 PDF, 보완 사유 선택지 영어.
- 기준 글자 크기 rem 전환(실기기 점검 뒤).

## 당회 확인이 필요한 항목 (이번 검토에서 추가)

1. 두 번째 관리자 지명(시범 시작 30일 안), 감사위원 확인(D30).
2. 장애 중 수표 금지와 종이→시스템 전환 날짜(D35).
3. 백업 보관 장소, 복호화 키 보관자(당회 서기), 7년 보관(D36).
4. 결재자 장기 부재 때 대신할 분.
5. 떠난 교인의 휴대폰·주소 보관 기간.
6. 종이 영수증 원본을 재정부에 내는지(중복 통제).

## 추가한 테스트

- pgTAP `04_m4_regressions_test.sql`(40건):
  - `anon`의 public 테이블 권한 0개. 서비스 전용 함수는 사용자가 부를 수 없다. 관리자가 있으면 첫 관리자 설정이 거부된다.
  - 같은 날 같은 금액 경고: 같은 작성자는 표시되고, 다른 작성자의 부서 경고는 그 작성자에게 안 보이고 결재자에게 보인다.
  - 작성자에게 보내지 못한 보완 요청이 막힌 건에 바로 오르고 "작성자 차례"로 나온다. 결재 3일은 막힌 건이 아니고 9일은 막힌 건이다.
  - 사무실 취소: 작성자가 사용 중이거나 결재 중인 건은 거부되고, 정지된 작성자의 보완 요청 건은 취소되며 감사 기록에 남는다.
  - 로그인 다시 연결: 본인은 안 되고 사유가 필요하다. 연결이 지워지고 "초대 전"이 되며, 대면 확인이 초기화되고 이전 메일로 안내되고 새 초대가 된다.
  - 정보 수정: 사유가 필요하고 메일을 바꾸면 이전 주소로 안내된다.
