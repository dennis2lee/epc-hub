# 맥 서버 운영 검토 (Fable 자문)

- 날짜: 2026-11-22
- 질문: 운영 서버를 Vercel + Supabase 클라우드 대신 개발 담당의 맥으로 하면 어떤가(적극 검토)
- 대상 기기: MacBook Air(M5, 32GB, 460GB, FileVault 켜짐, 개인 개발용 노트북)
- 결론: **D40 유지.** 운영은 클라우드로 한다. 맥은 교회 소유 기기를 따로 두어 주간 암호화 백업 보관, 복원 연습, 로컬 시험용으로 쓴다(D36 보관소 후보). 사용자 최종 결정 대기.

## 핵심 판단

| 항목 | 판단 |
|---|---|
| 개인 MacBook Air | 어떤 조건에서도 서버로 쓰지 않는다. 뚜껑을 닫으면 잠들고, 집 밖으로 나가고, 배터리·와이파이로 돌고, 개인 용도와 OS 업데이트로 재시작한다. 교인 개인정보가 개인 브라우징·개발 도구와 한 기기에 놓인다 |
| 전용 Mac mini | 최소 조건이다. 교회 소유, 유선 인터넷, UPS, 정전 뒤 자동 켜짐, 잠자기 끔, 잠긴 방, 다른 용도 금지 |
| FileVault | 켜면 정전 뒤 잠금 화면에서 멈춘다. 사람이 원격 잠금 해제(macOS 26, SSH)를 해야 한다. 끄면 무인 복구는 되지만 도난 때 7년치 재정 기록이 노출된다. 둘 중 하나를 골라야 한다 |
| Supabase 직접 설치 | 지금 쓰는 `supabase start`는 개발용이다. 키가 공개된 기본값이라 운영에 쓰면 안 된다. 공식 `supabase/docker` 구성에 고유 비밀값을 넣고, Postgres와 관리 화면은 외부에 열지 않는다. 업그레이드·보안 패치를 직접 해야 한다 |
| 외부 접속 | Cloudflare Tunnel이 가장 낫다. 다만 `epcsj.org` DNS를 Squarespace에서 Cloudflare로 옮겨야 한다. DNS를 Squarespace에 둔 채 쓰는 방식은 Business 이상 유료 요금제다. Tailscale Funnel은 교회 도메인을 쓸 수 없다. 공유기 포트 개방은 권하지 않는다 |
| 메일 | 맥에서도 Resend를 그대로 쓴다. Google Workspace 메일 중계는 교회 실제 메일함의 평판을 함께 쓰게 되고, 비밀번호 보관이 필요하다 |
| 백업·재해 | 클라우드 일일 백업이 없으니 매일 교회 밖으로 암호화 백업을 보내야 한다(예: Backblaze B2). 맥이 고장 나면 복구에 1~3일 걸린다. 개발 담당이 없으면 기한 없이 멈춘다 |
| 코드·문서 변경 | prod-guard, Cron(launchd), 환경변수, 백업 스크립트, 운영 스크립트, 배포·운영 문서를 다시 쓴다. 4~6일, 복원 연습과 실기기 점검을 다시 한다 |
| 비용 | 클라우드는 연 $300~540, 월 1시간 정도다. Mac mini는 약 $750~950을 한 번 내고 설정에 40~60시간, 매달 3~6시간이 든다. 돈은 약 2년에 본전이지만 시간까지 치면 본전이 안 된다 |

## 다시 검토할 조건

- 교회에 서버를 관리할 수 있는 자원봉사자가 두 명 있고, UPS가 있는 서버실이 있을 때
- 클라우드 비용이 월 $100을 넘을 때
- 데이터를 교회 안에 두라는 규정이 생길 때

## 맥 운영을 택한다면 필요한 당회 결정

- `epcsj.org` DNS 이전
- 7년치 기록·백업의 물리적 위치와 복호화 키 보관자
- FileVault를 끄고 무인 복구를 허용할지
- 장비 구입과 소유
- 허용할 장애 시간. D35(장애 중 수표 금지)와 맞물린다

출처: Fable 자문이 Apple(FileVault 원격 잠금 해제), Cloudflare(부분 DNS 설정, Tunnel FAQ), Tailscale(Funnel), Google Workspace(SMTP 중계 한도) 공식 문서를 확인했다.
