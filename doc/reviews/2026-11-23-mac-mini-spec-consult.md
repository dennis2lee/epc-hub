# 교회 맥미니 사양·설치 환경 자문 (Fable)

- 날짜: 2026-11-23
- 자문: Fable 1회 (문서와 운영 스크립트를 읽음, 파일 수정 없음)
- 계기: 사용자가 "운영 서버는 개인 맥미니가 아니라 교회 IT실에 비치하는 교회 맥미니"라고 바로잡고 추천 사양을 요청
- 결과: D49 (`doc/decisions.md`)
- 가격은 모두 대략값(미국, 세전)이다. 구매 전에 현재 가격과 구성을 다시 확인한다.

## 요약

| 질문 | 답 |
|---|---|
| 권장 사양 | 현행 기본 칩, **메모리 24 GB, SSD 512 GB** (약 $999) |
| 최소 사양 | 기본 칩, 16 GB, 256 GB (약 $599). 동작은 하지만 Colima 메모리를 낮추고, 디스크는 2~3년차에 모자란다 |
| 예산이 빠듯하면 | 16 GB · 512 GB (약 $799). 메모리보다 디스크를 먼저 올린다 |
| Pro 칩 | 필요 없음. 100명 규모에서 CPU는 남는다 |
| 가장 큰 발견 | 지금 백업 방식은 디스크를 영수증 용량의 약 6~7배 쓴다. 사양보다 백업 증분화가 더 근본 대책이다 |

## 1. 디스크: 백업이 가장 많이 쓴다

코드로 확인한 백업 흐름(`src/scripts/backup.mjs`, `src/ops/bin/backup-nightly.sh`):

1. 영수증 **전부**를 평문 폴더(`~/church/backups/backup-날짜/receipts/`)로 내려받는다.
2. 그 폴더를 `.tar`로 묶는다.
3. age로 암호화해 `.tar.age`를 만든다.
4. 암호화본을 Drive에 올리고, 로컬에는 최근 3개를 남긴다.

그래서 백업하는 동안 디스크에는 영수증 원본 1벌, 평문 폴더 1벌, tar 1벌, 새 암호화본 1벌, 남겨 둔 암호화본 3벌이 함께 있다.

| 가정 | 월 증가 | 7년 누적 영수증 | 7년차 로컬 최대 (약 6배) |
|---|---|---|---|
| 보통: 월 300건 × 2장 × 1.5 MB | 약 0.9 GB | 약 76 GB | 약 450 GB |
| 많음: 월 500건 × 3장 × 3 MB | 약 4.5 GB | 약 380 GB | 2 TB 이상 |

- 고정 사용량은 약 50~60 GB다: macOS 약 25 GB, Homebrew·Node, Docker 이미지 6~10 GB, 배포 폴더, 로그.
- Drive에도 매일 전체가 올라간다. 영수증이 30 GB면 매일 30 GB를 올리고, 매일 사본 31개만으로 약 1 TB가 된다. 교회 인터넷 업로드 속도와 Workspace Drive 용량도 함께 걸린다.
- **조치:** 백업을 증분 방식으로 바꾸는 후속 결정을 남은 일로 둔다. 영수증은 바뀌지 않으므로 새 파일만 올리면 된다. 시범 첫 달에 영수증 평균 크기를 재서 위 표를 고친다.
- 1 TB SSD(약 +$200)는 백업 방식을 그대로 둘 때만 의미가 있다. 방식을 바꾸는 쪽이 싸고 Drive 문제도 함께 풀린다.

## 2. 메모리

| 항목 | 사용량 (추정) |
|---|---|
| macOS + cloudflared + Tailscale | 4~5 GB |
| Colima VM 안 컨테이너 합계 (db, studio, storage, rest, meta, imgproxy, auth, 게이트웨이) | 2~2.5 GB (VM 상한 8 GB) |
| Next.js `next start` | 0.3~0.6 GB |
| 배포 때 `next build`, 백업 node 작업, 복원 연습 | 잠깐 2~4 GB 더 |

- **16 GB:** 평소에는 충분하다. 다만 VM을 8 GB로 두면 빌드와 백업이 겹칠 때 스왑이 생긴다. 그래서 VM을 6 GB로 낮춘다.
- **24 GB:** 지금 설정(`--cpu 4 --memory 8 --disk 60`) 그대로 여유가 있다.
- 메모리와 SSD는 사고 나서 늘릴 수 없다.

## 3. Colima 할당

| 맥미니 메모리 | 명령 |
|---|---|
| 24 GB 이상 | `colima start --cpu 4 --memory 8 --disk 60` (현행) |
| 16 GB | `colima start --cpu 4 --memory 6 --disk 60` |

- 공식 구성은 DB와 영수증을 `~/church/supabase/volumes/` 아래 맥 디스크에 둔다(바인드 마운트). 그래서 VM 디스크 60 GB에는 이미지만 들어간다. 설치 때 실제 위치를 확인한다.
- Colima 디스크는 늘릴 수만 있고 줄일 수는 없다.

## 4. 주변 장치와 IT실 환경

| 항목 | 권장 | 대략 가격 |
|---|---|---|
| UPS | 라인 인터랙티브, 순수 정현파, 850~1000 VA, USB HID(macOS가 자동 인식) | $140~200 |
| 기존 UPS를 쓸 때 | 배터리 제조 연도를 확인하고, 3~5년이 넘었으면 배터리를 교체한다. USB 신호가 잡히는지 리허설에서 확인한다 | $40~70 |
| UPS에 물릴 장비 | 맥미니와 함께 **모뎀·공유기·스위치**. 네트워크가 꺼지면 Tunnel도 끊긴다 | - |
| 인터넷 | 내장 기가비트 유선, Cat6. Wi-Fi는 끈다 | $10 |
| 고정 주소 | 공유기에서 DHCP 예약. 포트는 열지 않는다 | - |
| 외장 SSD, Time Machine | 필요 없음. 평문 사본만 하나 더 생긴다 | - |
| HDMI 더미 플러그 | 필요 없음(관리는 SSH). 화면 공유를 자주 쓸 때만 산다 | ($8) |
| 현장용 모니터·유선 키보드 | IT실에 둔다. FileVault 잠금을 현장에서 풀 때 쓴다 | 기존 것 |
| 환기·온도 | 사방 5 cm 이상 띄우고, 실온 10~35°C. 다른 장비 위에 쌓지 않는다 | - |
| 잠금 | IT실 잠금, 잠금 브래킷 또는 케이블 | $30~50 |
| 표시 | 본체·전원 코드·UPS에 "교회 지출청구 서버. 끄거나 뽑지 마시오. 연락처" | - |

정전 복구 주의: UPS 잔량 때문에 맥이 스스로 꺼졌는데 UPS가 꺼지기 전에 전기가 돌아오면, 맥은 전원이 끊긴 적이 없어 자동 켜짐(`autorestart`)이 동작하지 않을 수 있다. 그래서 매일 06:00 전원 켜기 예약(`pmset repeat wakeorpoweron`)을 함께 건다. 실제로 동작하는지는 UPS 코드를 뽑는 리허설에서 확인한다.

## 5. 교회 소유가 되면서 바뀌는 관리

| 항목 | 권장 |
|---|---|
| 자산 등록 | 교회 비품 대장에 모델, 일련번호, 구입일, 구입가, 위치, 담당자를 적는다. 영수증은 교회 명의로 받는다 |
| macOS 관리자 | `church` 계정. 비밀번호와 FileVault 복구 키는 봉투에 넣어 당회 서기와 기술 담당 2명이 보관한다. SSH는 사람마다 다른 키로 접속해 누가 들어왔는지 구분한다 |
| Apple ID | 로그인하지 않는다. iCloud·나의 찾기를 켜면 담당자가 바뀔 때 활성화 잠금이 문제가 된다 |
| Tailscale | `tech-media@kepc.org` 소유(D45와 같은 원칙) |
| AppleCare+ | 선택(3년 약 $99). 수리하는 동안에는 어차피 다른 맥으로 복원해야 하므로 복원 절차가 더 중요하다 |
| 교체 주기 | 5~6년, 또는 macOS 보안 업데이트가 끝날 때. 예산을 미리 잡는다 |
| 폐기·양도 | 새 서버로 옮겨 확인한 뒤 "모든 콘텐츠 및 설정 지우기", 비밀값 교체, 비품 대장에 날짜 기록 |
| 도난·분실 | FileVault가 기록을 보호한다. 그래도 비밀값을 모두 바꾸고, 백업으로 새 기기에 복원하고, 당회에 보고한다 |
| 전용 원칙 | 교회 소유여도 지킨다. 방송·자막·사무용으로 함께 쓰지 않는다 |

## 6. IT실에 두면서 달라지는 위험

| 위험 | 대응 |
|---|---|
| 주중 무인 + FileVault: 정전 뒤 잠금 화면에서 멈춘다. 그 단계에서는 Tailscale이 돌지 않고, SSH 잠금 해제는 같은 네트워크에서만 된다 | ① 교회 네트워크에 Tailscale을 설치한 작은 중계 기기를 상시 두고 거기서 푼다($60~100) ② 주중에 갈 수 있는 사람을 정한다 ③ FileVault를 끈다(당회 결정). 어느 쪽이든 리허설에서 실제로 해 본다 |
| 주중에는 아무도 보지 않는다 | healthchecks.io 알림을 필수로 두고, 받는 사람을 2명으로 한다 |
| 손님 Wi-Fi·방송 장비와 같은 망 | 손님 Wi-Fi를 분리한다(게스트 망·VLAN). 맥미니는 내부 유선망에 두고, 방화벽을 켜고, SSH는 관리자만 쓴다. 앱·DB·API는 이미 127.0.0.1에만 묶여 있다 |
| 행사·공사 때 전원 차단, 멀티탭 뽑힘 | 표시를 붙이고, UPS는 벽 콘센트에 바로 꽂고, 시설 담당에게 알린다 |
| 교회 인터넷 회선과 업로드 속도 | 업로드 속도를 잰다. 백업 증분화와 연결된다 |
| 열쇠 가진 사람이 많음 | FileVault를 유지할 근거다. 현장 화면은 자동으로 잠근다 |
| 주중 냉방 정지 | 여름 한 주 동안 온도를 기록한다 |
| 자원봉사 담당자 교체 | 계정은 모두 교회 주소 소유로, 봉투로 보관하고, 인수인계 절차를 `doc/operations.md`에 둔다 |
