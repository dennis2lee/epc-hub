# 맥미니 운영 레드팀 검토 (운영 스크립트·Tunnel·백업)

- 날짜: 2026-11-22
- 검토자: Fable 보안·운영 레드팀 1개
- 대상: `src/ops/**`, `src/scripts/backup.mjs`, `src/scripts/restore-receipts.mjs`, `src/lib/prod-guard.ts`, 접속자 IP 처리, `doc/deploy.md`, `doc/operations.md`
- 관련 결정: D47 (`doc/decisions.md`)
- 조치 확인: 개발용 MacBook Air에서 두 번째 리허설(`doc/reviews/2026-11-22-mac-mini-rehearsal.md` 2차)

## 요약

높음 5건 가운데 두 건은 보안 문제였다.
- 로그인 코드 대입을 막는 IP별 제한이 없었다. Supabase Cloud가 해 주던 일이다.
- Tunnel 경로 허용 목록을 `..`로 우회해 Studio(관리 화면) 로그인 창에 닿을 수 있었다.

나머지 세 건은 운영 첫날 바로 터질 문제였다.
- 배포 스크립트가 개발용 패키지를 빼고 설치해 빌드가 실패한다. 1차 리허설에서 배포 스크립트를 돌리지 않아 놓쳤다.
- 공백이 있는 `MAIL_FROM` 때문에 설정 파일 읽기가 실패한다.
- 영수증이 1,000개를 넘거나 내려받기가 실패해도 백업이 "성공"으로 끝난다.

모두 고쳤고, 2차 리허설에서 배포 스크립트와 운영 빌드까지 실제로 돌려 확인했다.

## 보류한 것

- 가입 전 훅(초대받은 주소·카카오 계정만 계정 생성 허용). D27의 남은 위험을 닫지만 인증 훅 시험이 필요하다. 시범 운영 중에 한다.
- 로그인 코드 8자리. 어르신 입력 부담 때문에 6자리를 유지하고, 요청 제한으로 막는다.
- 정전 시 Postgres 데이터 안전성(Colima 가상 디스크). UPS와 매일 백업으로 대신하고, 맥미니에서 실제로 전원을 뽑아 본다(`doc/deploy.md` 8장).
- 컨테이너가 맥의 127.0.0.1에 닿을 수 있다(리허설에서 확인). 감사 기록의 접속자 IP를 위조할 수 있는 정도라 받아들인다.

## 리허설 뒤 정리

복호화한 백업 폴더와 리허설용 age 키는 지웠다. 리허설용 Supabase 설치본과 설정 파일(가상 데이터, 리허설 전용 비밀값)은 다음 리허설을 위해 `build/rehearsal/`에 남긴다. `build/`는 커밋하지 않는다.
