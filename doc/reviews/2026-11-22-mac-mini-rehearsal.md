# 맥미니 운영 리허설 (개발용 MacBook Air)

- 날짜: 2026-11-22
- 목적: `doc/deploy.md`의 맥미니 절차와 `src/ops/` 스크립트가 실제로 동작하는지, 맥미니를 받기 전에 같은 macOS·Colima 환경에서 확인한다.
- 장소: 개발용 MacBook Air(M5, macOS 26.5, Colima). 설치 폴더는 `build/rehearsal/`(커밋하지 않음). 비밀값은 리허설용으로 새로 만들었고 리허설 뒤 버린다.
- 결과: 모든 단계 통과. 리허설 중에 스크립트 결함 4건을 찾아 고쳤다(아래).

## 리허설에서 찾아 고친 것

| # | 문제 | 조치 |
|---|---|---|
| 1 | Colima는 홈 폴더 밖(임시 폴더)을 컨테이너에 연결하지 않아 게이트웨이 설정 파일을 읽지 못했다 | 모든 운영 파일을 `~/church` 아래에 두도록 절차서에 명시 |
| 2 | 설정 합치기가 빈 값을 건너뛰어 예시 비밀번호(`fake_mail_password`)가 남았고, "SMTP_PASS 비어 있음" 검사를 통과했다 | 교회 설정 값으로 항상 덮어쓰게 고침 |
| 3 | 복원에서 `postgres` 역할로는 auth·storage 표를 비우고 트리거를 끌 수 없었다 | 공식 이미지의 슈퍼유저 `supabase_admin`으로 불러오게 고침 |
| 4 | 재정 E2E가 이전 실행과 같은 금액·날짜라 새 중복 경고(D34)에 걸렸다 | 실행마다 금액을 바꾸게 고침. 규칙 자체는 맞게 동작함 |

이 밖에 Supabase CLI가 사람 확인 없이 원격 DB를 바꾸지 않는다는 것을 확인했다. 맥미니에서 사람이 실행하면 확인 질문이 나온다. 복원 연습용 버리는 스택에서만 `ASSUME_YES=1`로 넘긴다. GoTrue 설정 이름(카카오 이메일 선택, OTP 길이·만료, 발송 한도)은 GoTrue 원본 코드에서 확인했다.

## 맥미니에서 처음 확인할 것 (리허설로 대신할 수 없는 것)

- Cloudflare Tunnel과 실제 도메인(`www`, `api`), 경로 제한(`/auth`·`/rest`·`/storage`만, `/auth/v1/admin` 차단)
- Resend SMTP 실제 발송과 받은편지함 도착
- 카카오 로그인(실제 키)
- 정전 뒤 자동 켜짐, FileVault 잠금 해제 후 자동 재시작, UPS 종료
- rclone Google Drive 연결과 매일 02:30 실행, healthchecks.io 알림

## 2차 리허설 (레드팀 반영 뒤)

레드팀 지적(`doc/reviews/2026-11-22-mac-mini-ops-redteam.md`)을 고친 뒤, 커밋 4d41c81(CI 통과)으로 다시 했다. 이번에는 배포 스크립트를 실제로 돌렸다. 맥미니의 `sudo`·`launchctl` 자리에는 앱을 대신 띄우는 리허설 전용 대역을 썼다.

| # | 단계 | 결과 |
|---|---|---|
| 1 | 강화한 설정으로 스택 재시작 | 연결 풀러 포트 없음, 파일 한도 5MB, IP별 제한 헤더 적용 확인 |
| 2 | Tunnel 규칙 판정(`cloudflared ingress rule`) | 허용 경로만 통과, 가입·관리·데이터 API·Studio·우회 경로 모두 404 |
| 3 | `deploy.sh`: GitHub에서 받기 → CI 확인 → 빌드 → 마이그레이션 → 전환 → `/api/health` | 통과. 시험 화면 404 |
| 4 | 운영 빌드(`next start`)로 Playwright. 공개 주소(`localhost:8000`)와 서버 주소(`127.0.0.1:8000`)를 다르게 둠 | 6건 통과. 쿠키 이름 고정 확인, 영수증 열람이 공개 주소로 리다이렉트되어 이미지 200 |
| 5 | 코드 확인 IP별 제한 | 같은 IP 31번째부터 429, 다른 IP는 영향 없음 |
| 6 | `backup-nightly.sh` | 영수증 13개 해시 일치, `daily/`와 `monthly/`에 올라감 |
| 7 | 운영 서버에서 복원 시도 | 거부됨 |
| 8 | 전부 삭제 → 빈 스택 → `restore.sh`(한 트랜잭션, 버전 확인) | 통과. 건수가 백업 전과 같음(감사 기록은 영수증 재업로드 13건만큼 늘어남) |
| 9 | 복원 뒤 앱 재시작, 해시 확인, Playwright | 상태 확인 200, 해시 13/13 일치, 6건 통과 |
| 10 | 같은 커밋 재배포 → `--rollback` | 새 폴더에 빌드, 되돌리기 뒤 상태 확인 정상 |

맥미니에서만 확인할 수 있는 것(부팅 시 시스템 서비스, FileVault 원격 잠금 해제, UPS, 실제 도메인·메일·카카오·Drive)은 `doc/deploy.md` 8장 점검으로 한다.
