결재 흐름

지키는 원칙

1한 사람이 다 하지 못한다

  • 작성자 ≠ 결재자 ≠ 지급자
  • 수표 기록자는 결제 확인을 하지 않는다 (대체자 없을 때만, 표시)
  • 관리자는 자기 권한을 못 만진다

2규칙은 서버가 지킨다

  • 상태는 정해진 데이터베이스 규칙으로만 바뀜
  • 화면이 실수해도 서버가 거부
  • 오래된 화면의 버튼은 "그 사이 바뀜"으로 거부

3증거는 지우지 않는다

  • 승인 순간의 내용을 지문처럼 저장
  • 제출된 영수증 파일은 남김
  • 감사 기록은 추가만 가능

4멈춘 결재를 찾아낸다

  • 메일이 실패해도 결재는 진행
  • 결재 8일째·재정 10일째부터 막힌 건 목록
  • 매일 아침 점검 메일

5민감 정보를 받지 않는다

  • 계좌번호·사회보장번호·세무 서류·신분증 없음
  • 수표만 쓰므로 영문 이름과 주소면 충분

6기록이 교회 안에 있다

  • 교회 IT실의 교회 맥미니에 저장
  • 매일 암호화해 교회 Google Drive로
  • 복호화 키 사본을 두 사람이 따로 보관

역할별 사용법

작
작성자 · 부서원 누구나
  1. 홈에서 새 지출청구서 쓰기 → 부서 선택
  2. 사용 목적, 사용일, 총액(세금·팁 포함) 입력
  3. 영수증 사진·PDF 첨부 (최대 20장. 아이폰 HEIC 사진은 브라우저가 열 수 있으면 올리기 전에 JPEG로 바꾸고, 안 되면 카메라 설정을 안내)
  4. 수표 받는 방법: 주일 재정부 수령 또는 우편
  5. 결재 올리기(제출) → 문서번호 발급, 부장에게 메일. 홈에서 "지금 누구 차례"가 보임
  6. 보완 요청이 오면 메일 수신 → 고쳐서 다시 제출 (부장부터 다시)
  7. "수표가 발행되었습니다" 메일 → 주일에 수령 또는 우편 도착
결
결재자 · 부장, 담당 장로
  1. 메일(또는 카톡 공유)로 결재 요청을 받음. 메일 제목에 작성자·금액·목적이 보임
  2. 링크 또는 홈의 내가 볼 청구서에서 열기 (오래된 순)
  3. 내용·영수증, 다시 올라온 건이면 이전 보완 요청 사유 확인
  4. 승인 또는 보완 요청(사유 필수) → 확인 창에서 금액·수취인·영수증 장수를 한 번 더 봄
  5. 승인은 되돌릴 수 없음. 승인하면 본인에게 "승인하셨습니다" 메일
재
재정부원 · 재정 담당 장로는 처리할 재정부원이 없을 때만 (본인 청구, 그 회차 결재자 등)
  1. 재정부 화면의 서류 확인 대기에서 청구 열기. 결재자 1인·중복 의심 표시 확인 (중복 의심이면 확인 사유 한 줄)
  2. 서류 확인 또는 서류 보완 요청(사유 필수, 부장부터 다시)
  3. 수표 발행 대기에서 수표를 쓴 뒤 수표 발행 기록: 번호(숫자만)·발행일·수표에 쓴 금액. 같은 수취인의 여러 청구를 한 장으로 묶기 가능. 금액이 합계와 다르면 거부
  4. 수표 목록 · 은행 결제 전에서 은행 명세서를 보고 은행 결제 확인 (수표를 기록한 사람이 아닌 다른 사람이)
  5. 잘못 쓴 수표는 무효(사유 5자 이상) → 청구가 수표 대기로 돌아감. 번호는 다시 쓰지 않음
  6. 월별 지급 CSV, 오늘 기준 미지급·미결제 CSV 내려받기
관
관리자 · 사무간사, 개발 담당
  1. 부서 만들기, 사람 등록, 직책 배정(부장·장로·재정부원·재정 담당 장로, 시작·종료일)
  2. 초대 링크 만들기 → 카톡·문자로 전달. 결재 관계자는 대면 확인
  3. 막힌 건 목록을 보고 해당 결재자에게 전화·카톡. 결재자가 바뀌었으면 직책을 고친 뒤 현재 단계를 새 담당자에게 다시 배정
  4. 작성자 차례로 오래 멈춘 건 확인. 작성자가 정지·미연결이면 그 청구를 사유를 적고 취소 (관리자 본인 청구는 불가)
  5. 교인 정보 수정, 정지·재활성, 로그인 다시 연결
  6. 관리자·감사위원 권한 부여·회수 (근거 필수, 본인 불가)
감
감사위원
  1. 작성 중을 뺀 모든 청구와 수표 기록을 읽기만 함 (작성자가 뺀 영수증도 볼 수 있음)
  2. 분기마다 지급 목록과 은행 명세서를 대조하고 인쇄본에 서명 (운영 규정)

버튼 하나를 누르면 아래 다섯 층을 지나갑니다. 권한 판단은 ④·⑤에서만 합니다. 위층이 실수해도 DB가 거부합니다.

①
화면src/app/**/page.tsx

③

4작성자 본인이 아닌지author_cannot_act

7보완 요청이면 사유가 있는지reason_required
8단계에 결정·사유·시각·내용 해시·접속 정보 기록—
9다음 단계로 넘기거나 재정부 확인 대기로 바꾸고 버전 +1—
