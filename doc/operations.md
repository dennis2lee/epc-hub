# 운영 절차서

교회 사무실(사무간사)과 기술 담당이 함께 보는 문서다. 인쇄해서 사무실에 둔다(A4 2~3쪽). 화면 이름은 앱에 보이는 그대로 적었다.

- 문서 갱신일: 2026-11-21 (시범 운영 전 초안)
- 문의 창구: 교회 사무실 하나. 교인은 사무실로, 사무실은 기술 담당에게 연락한다.
- 기술 담당: (이름·연락처 기입) / 두 번째 기술 담당: (기입)

## 1. 역할

| 누가 | 하는 일 | 하지 않는 일 |
|---|---|---|
| 사무간사(관리자) | 사람 등록, 초대 링크 보내기, 대면 확인, 직책 배정, 막힌 건 처리 | 청구서 결재, 수표 기록 |
| 개발 담당(관리자) | 배포, 백업 확인, 장애 대응 | 교인 데이터 직접 수정 (상태 변경은 DB 함수로만) |
| 재정부원 | 서류 확인, 수표 기록, 무효 처리, 은행 결제 기록(다른 사람이 쓴 수표만) | 본인 청구·본인이 결재한 청구의 처리 |
| 감사위원 | 수표 목록·CSV·감사 기록 열람, 분기 대사 서명 | 기록 변경 |

## 2. 새 교인 등록

1. 관리자 화면 → **사람 등록**: 이름, 휴대폰 번호, (있으면) 메일, 수표용 영문 이름.
   - 부장·장로·재정부·관리자는 "결재자·재정부·관리자(대면 확인 필요)"에 표시한다.
2. 그 사람 줄의 **초대 링크 만들기** → **카톡·문자로 보내기**. 링크는 7일 동안 유효하다.
3. 받은 분은 본인 휴대폰에서 링크를 열고 휴대폰 번호 뒤 4자리를 넣는다.
   - 다섯 번 틀리면 링크가 잠긴다. 새 링크를 만들어 보낸다(이전 링크는 자동으로 무효).
4. 결재 관계자는 "사무실 확인 중"으로 기다린다. 주일에 얼굴을 보고 **대면 확인 완료**를 누른다.
   - 관리자는 자신을 대면 확인할 수 없다. 다른 관리자가 한다.

## 3. 직책이 바뀔 때 (부장·장로·재정부 교체)

1. 관리자 화면 → **직책 배정**: 새 사람, 부서, 직책, 시작일.
2. 이전 사람의 직책은 종료일을 넣어 끝낸다. 같은 기간에 같은 직책이 겹치면 저장되지 않는다.
3. 이미 결재 중인 청구는 원래 결재자에게 남아 있다. 옮겨야 하면 **막힌 건**에서 **현재 직책자에게 다시 배정**을 누르고 이유를 적는다.

## 4. 매일·매주 할 일

| 언제 | 누가 | 할 일 |
|---|---|---|
| 매일 아침 메일 | 관리자 | "막힌 청구서 N건" 메일을 연다. 이유별로 아래 5장을 따른다 |
| 매일 아침 메일 | 재정부 | "재정부 확인 필요" 메일: 90일 넘은 미결제 수표, 처리자 없는 청구 |
| 월요일 | 관리자 | 막힌 건이 없으면 "이상 없음" 메일이 온다. **이 메일이 안 오면 매일 점검이 멈춘 것이다.** 기술 담당에게 알린다 |
| 매월 초 | 재정부 | 재정부 화면 → 지난달 **지급 내역 CSV**를 받아 회계 프로그램에 넣는다. 무효 수표는 금액 0으로 나온다 |
| 분기 말 | 재정부·감사위원 | **오늘 기준 미지급·미결제 CSV**와 은행 명세서를 맞춘다. 지급 목록 = 은행 결제분 + 미결제 수표 |

## 5. 막힌 건 처리

| 화면에 보이는 이유 | 할 일 |
|---|---|
| 오래 기다리는 중 | 그 결재자에게 전화하거나 카톡으로 링크를 다시 보낸다 |
| 결재자 확인 전·정지 | 대면 확인을 하거나, 정지가 맞다면 직책을 바꾸고 다시 배정한다 |
| 부장 미지정 / 담당 장로 미지정 | 직책을 배정한다. 작성자에게 다시 올려 달라고 알린다 |
| 본인 외 결재자 없음 | 부서 구조를 확인한다(당회 결정이 필요할 수 있다) |
| 처리할 재정 담당 없음 | 재정부원이나 재정 담당 장로를 배정·대면 확인한다 |
| 알림 메일 실패 — 전화로 알려 주세요 | 다음 결재자에게 전화한다. 그분의 메일 주소를 '내 정보'에 넣어 달라고 부탁한다 |

## 6. 수표 관련

- **수표를 잘못 썼을 때**: 재정부 화면 → 수표 목록에서 **무효 처리** → 사유를 적는다(5자 이상).
  - 청구서는 "수표 발행 대기"로 돌아간다. 새 수표를 다른 번호로 기록한다.
  - 무효 번호는 다시 쓸 수 없다. 받은 분에게 이전 수표를 돌려받는다.
- **은행 결제 기록**: 수표를 기록한 사람이 아닌 다른 재정부원(또는 재정 담당 장로)이 은행 명세서를 보고 **결제됨 기록**을 누른다.
  - 잘못 눌렀으면 **결제 기록 취소**로 사유를 적고 되돌린다.
- **서류에 문제가 있을 때**: 수표 발행 전이면 서류 확인 뒤에도 청구서 화면에서 **서류 보완 요청**을 보낼 수 있다.

## 7. 이럴 때는

### 로그인이 안 된다고 할 때

1. 카톡 안에서 열었으면 화면의 **브라우저로 열기**를 누르게 한다.
2. 메일 코드: 스팸함을 보게 한다. **코드 다시 받기**는 1분 뒤에 된다.
3. "등록되지 않은 계정입니다": 초대 링크를 아직 열지 않은 것이다. 새 초대 링크를 보낸다.
4. 그래도 안 되면 기술 담당에게 이름·시각·화면 사진을 보낸다.

### 사이트가 안 열릴 때

1. 다른 휴대폰·와이파이로 열어 본다.
2. 기술 담당에게 연락한다. 기술 담당은 Vercel·Supabase 상태 페이지를 확인한다.
3. 하루 이상 걸리면 종이 청구서로 받고, 복구 뒤 작성자가 시스템에 다시 올린다(영수증 사진 포함).

### 백업이 실패했다는 메일이 올 때

기술 담당이 GitHub Actions 기록을 확인하고 다시 실행한다. 이틀 연속 실패하면 Supabase 대시보드에서 수동 백업을 받는다. (백업 자동화는 시범 운영 중 추가)

### 관리자 계정을 잃었을 때 (휴대폰 분실 등)

다른 관리자가 그 사람을 **정지**하고, 새 초대 링크로 다시 연결한 뒤 대면 확인한다. 관리자가 한 명뿐이면 기술 담당이 비상 절차(당회 서기 입회)로 처리하고 감사 기록에 남긴다.

## 8. 비밀값 보관

| 무엇 | 어디에 | 누가 |
|---|---|---|
| Supabase 프로젝트 소유권 | 교회 공용 계정 (개인 계정 금지) | 기술 담당 2명 |
| Vercel 프로젝트 | 교회 공용 계정 | 기술 담당 2명 |

| `SUPABASE_SECRET_KEY`, `CRON_SECRET`, `RESEND_API_KEY` | Vercel 환경변수에만. 문서·카톡·메일에 쓰지 않는다 | 기술 담당 |
| 이 문서의 연락처 표 | 사무실 인쇄본 | 사무간사 |

키를 바꿨으면 이 문서 맨 위 갱신일을 고친다.

## 9. 시스템을 그만 쓸 때 (종료 계획)

1. 재정부 화면에서 전체 기간 지급 내역 CSV를 월별로 받는다.
2. 모든 청구서 인쇄본을 PDF로 저장한다.
3. 영수증 버킷을 통째로 내려받아 교회 보관 매체 두 곳에 둔다.
4. 종이 청구서로 돌아간다. 감사 기록 DB 덤프는 7년 보관한다(CPA와 확인).
